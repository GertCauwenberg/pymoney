# AGENTS.md

PyMoney: double-entry accounting. Three independently deployable components, each
with its own Makefile, pyproject/package, tests and coverage gate. The root
`Makefile` only delegates. Design decisions and technical notes live in
[docs/DESIGN.md](docs/DESIGN.md).

- `server/` — Python package `pymoney-core` (`src/pymoney`): `core` (pure stdlib,
  no runtime deps), `store` (SQLAlchemy Core), `quotes`, `importers`, `api`
  (FastAPI). Ships `docs/openapi.json`.
- `desktop/` — Python package `pymoney-desktop` (`src/pymoney_desktop`), PySide6.
  Depends on `server[api]`. Shares one `.venv` with the server at the repo root.
- `frontend/` — npm workspace: `@pymoney/core` (no DOM) + `@pymoney/web` (React),
  plus Playwright e2e.

## Commands

```bash
make install              # .venv (server + desktop) + npm ci (frontend)
make check                # what CI runs for all three, plus i18n-check
make -C server test       # fast: memory + sqlite, dev Hypothesis profile
make -C server test-ci    # CI suite: ci profile, coverage gate (90%)
make -C server test-all   # adds postgres
make -C server test-thorough  # 5000 Hypothesis examples; run when touching rounding
make -C desktop test      # sets QT_QPA_PLATFORM=offscreen itself
make -C frontend check    # generate types + drift check + typecheck + test + build
run.sh                    # starts API + Vite dev server together
```

Single test (server): `.venv/bin/pytest tests/test_posting.py -k name --stores=memory`.
`--stores` is a repo-local pytest option (`memory,sqlite,sqlite-file,postgres`);
the whole behavioural suite is parametrised over it. `postgres` needs
`PYMONEY_TEST_DATABASE_URL`; set `PYMONEY_REQUIRE_POSTGRES=1` to fail instead of
skip. `pgserver` gives a local throwaway PostgreSQL.

## Generated files — do not hand-edit

- `server/docs/openapi.json` — regenerate with `make -C server openapi`. CI fails
  if it is stale; the frontend types come from it.
- `frontend/packages/core/src/generated/openapi.d.ts` — `npm run generate`
  (`frontend/`). `npm run check` fails on drift.
- `frontend/packages/core/src/generated/nl.json` — copied from the server by
  `scripts/i18n.py`.
- `server/src/pymoney/store/migrations/versions/*` — Alembic autogenerated;
  review by hand. Excluded from mypy; ruff lint only ignores E501 there.

## Conventions and gotchas

- **i18n**: `server/src/pymoney/i18n/nl.json` is the single catalogue, keyed by the
  English source string. Every user-visible string needs a Dutch translation:
  `t("…")` (web), `_("…")` (desktop), `translate("…")` (server). `make i18n-check`
  fails on missing/stale keys or a stale frontend copy.
- **Warnings are errors** in both pytest configs (`filterwarnings = ["error"]`).
- Coverage gates: server `fail_under = 90`, desktop `85`. `pymoney.core` measures
  as the source path `src/pymoney`.
- **Money is never a float.** Amounts are integer minor units; the frontend uses
  `BigInt` string math; rates are exact `num`/`den`. Rounding invariants are
  enforced by property tests in `server/tests/test_posting.py`.
- **One writer per book** (design decision #14): the API holds one `Book` object
  per book id with a per-book lock; requests for the same book serialise. The
  store is the only mutator. Run the API single-worker.
- **Migrations are a deployment step**, never a start-up side effect:
  `python -m pymoney.store.migrate` (works without `alembic.ini` in the image).
- **Attachment bytes live on disk**, not in the DB (`PYMONEY_ATTACHMENTS_DIR`).
  Backups must capture the database and that directory together.
- `@pymoney/core` must not import `react-dom`, `react-router` or DOM types (its
  tsconfig only has `lib: ["ES2022"]`).
- Frontend unit/component tests use a fake server; `frontend/e2e` (Playwright)
  runs the real API + Vite. E2E needs `make -C ../server install` first.
- Python targets 3.12+; ruff line-length 90, mypy is clean. CI runs Python 3.12
  and 3.13 for the server.
